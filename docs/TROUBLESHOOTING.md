# 排错索引（症状 → 去查哪一层）

> 这份文件是**索引**，不是教程。它的用途只有一个：
> **下次遇到"没改"或"丢了"，能在 5 分钟内定位到哪一层，而不是像 2026-10-11 那次来回 6 轮。**
>
> 为什么需要它：那几天踩的 8 个坑，**现场表现几乎都是同一句话** ——
> 「文档没改」或者「内容丢了」。同一句话背后可能是六个完全不同的层次。
> 每一层的证据都写在日志里，但**得知道去读哪个日志、看哪一行**。

---

## 0. 先记住三句话

1. **先让证据说话，再改代码。** 那几天有两次"看截图猜了两轮"，都是错的；
   让浏览器/宿主报一次数，一次就定位了。
2. **每个"沉默分支"都要留痕。** 处理函数"没事可做时静默返回"是排错的头号敌人 ——
   「钩子没触发」和「触发了但没活干」在日志里长得**一模一样**。
3. **测试要验牙。** 写完测试，把被修的那行临时去掉，**它必须挂**；
   不挂就说明这条测试证明不了那个修复。

## 1. 症状：**文档没改**（选区编辑区那一整条链）

这条链跨六层，任何一层错都表现为同一句话。**按顺序读 `%TEMP%\ccv-selctx.log`**：

```
① 有没有「[拼接] 已注册（挂到 ctx.root ✓…）」这一行？
   没有 → 宿主没重启，新模块没加载          （改宿主必须完全重启 dsh web）

② 有没有「[拼接] 钩子触发第 N 次」？
   没有 → 事件作用域错了。事件只往上冒到**祖先**，
          插件自己的 ctx 是 agent 作用域的**兄弟分支**，收不到 ✗
          必须挂 ctx.root —— 见 src/host/14-scratch-splice.js 的注册段

③ 有没有「[拼接] 用注入时留下的引用 N 条」？
   没有 / 显示"没有注入时留下的引用，退回现解析：0 条"
        → 缓存被"空读"覆盖了。同一轮里注入会被调多次，而**不同通道读出来不一样**：
          队列那条带引用 ✓ / 界面那条不带 ✗
          规则：**只在看到引用时才写缓存**，读出来就立刻清空
          —— 见 src/host/13-selref-context.js 里 ccvLastTurnRefs 的注释

④ 有没有「[拼接] 引用 N 条，其中配到编辑区 0 个」？
   有 → 配对断了。看 pinCode 绑定：建区时 host 记的 pinCode 与注入时找的那笔上报
        必须是同一笔（ccvPinFind 的 remaining 规则：第 N 条引用 ↔ 第 N 笔上报）

⑤ 有没有「[拼接] 没拼：…」？
   有 → 过期校验没过，而且它**故意不拼**（设计稿第九节：不静默兜底）：
        "分不出该改哪一处" / "这段原文在主文档里已经找不到了"
        这时**不要改代码去"让它拼上"** ✗ —— 那是防"静默改错地方"的最后一道闸

⑥ 全都有「拼入」但文件没变？
   → 落盘/刷新那一层：见第 2 节
```

**相关代码**：`src/host/14-scratch-splice.js`（拼接）·
`src/host/13-selref-context.js`（注入与配对）· `src/host/09-http.js`（建区）

## 2. 症状：**内容丢了 / 登记重置了**

```
读宿主控制台（不是浏览器日志）里有没有：
  「restore: 保留内存里未落盘的改动（不覆盖）」
      → 命中过守卫：内存里有比文件新的内容，已经保住了 ✓
  「autosave failed: …」
      → 落盘失败（OneDrive 占用 / 磁盘满 / 权限）—— 内容还在内存里，dirty 仍为 true

机制（2026-10-14 修）：restore() 会在**同一个进程里被重跑**
  （会话重启 / 插件重载），而它原本无条件「从文件读内容 + 覆盖内存」✗
  → 内存里比文件新的那份被吃掉 ✗ 而且 dirty 被设成 false，连"还没存"都看不出来 ✗
三道闸（都在 src/host/04-persistence.js）：
  ① restore() 最前面先 await flushDirty()      —— 先落盘再读文件
  ② 绝不覆盖「内存里有未保存改动」的那一份      —— 落盘失败时兜底
  ③ 每轮结束落一次盘（turn-stopping / turn/end）—— 把暴露窗口从"几轮"缩到"一轮内"
```

**回归测试**：`tools/test-host-restore.cjs`（[2a]/[2b] 就是那个现场）

## 3. 症状：**改了、部署了，界面里没变**

```
先看浏览器控制台里那行版本号：
  「client v8 已挂载」+「挂载自检: …」
  → 版本没变 = 页面没刷新（客户端改动只需刷新）
  → 版本变了但行为没变 = 看下一段

再看是不是装到了**另一个 profile**：
  $DSH_HOME/profiles/<名字>/node_modules/collab-canvas
  这台机器上有 desktop 和 web 两份，跑的是哪份取决于怎么启动的 ✗
  所以部署要用 `npm run deploy`（扫全部 profile），不是 deploy:one ✗
  —— 见 tools/deploy-all.cjs 的注释（那次"部署了界面没变"就是这么来的）

宿主改动（src/host/*.js）必须**完全重启** dsh web；客户端（src/client / lib）刷新即可。
```

## 4. 症状：**查看器接管后一片空白**

```
两条都踩过，症状一样，原因完全不同：
  ① 组件返回 null（没渲染任何东西）
     —— 看控制台那行「React=没有 props键=…,kind=text 正文字数=5350」
        正文字数正常但没画出来 → 组件提前 return 了
  ② 内容 props 取错了位置
     —— content 是**顶层 prop**，不是 props.owner.content ✗
        （官方源码里是 MarkdownBody({ content, ... })）
规矩：**任何意外都不许变成空白**，把话说明白（"拿不到内容"/"不认这种内容"）
```

## 5. 症状：**段落之间凭空多一行**

```
实测数字：段落间距 38px，而边距只有 7px → 38 ≈ 24.5(一整行) + 7 + 7 ✓ 正好对上
原因：渲染器产出的 HTML 在标签之间带换行（</p>\n<p>），
      而容器继承了查看器的 white-space: pre-wrap → 每个换行被当成真换行 ✗
修法：容器显式 whiteSpace:'normal' + html.replace(/>\s*\n\s*</g, '><')
注意：只吃 `>` 和 `<` 之间的换行 —— <pre> 里的换行是内容，不会被误删 ✓
```

## 6. 症状：**两条引用粘在一行 / 插不进去**

```
① 两条引用粘在一行：插胶囊前必须先插一个换行，而换行的派发会推进 draftRev，
   状态是异步更新的 ✗ → 必须**轮询等 rev 变化**再派发胶囊（waitDraftRevChanged）
② 第二条插不进（官方事件失败，但手动 @ 可以）：
   胶囊在**两套投影**里长度不同 ——
     探测投影占 1 个字 / 剪贴板投影占一整串（InputState.draft 用的是后者）
   草稿空着时两套相等 → 第一条永远成功；有胶囊就差「串长 − 1」→ 必然失败 ✗
```

## 7. 症状：**改反了 / 改到另一处**

```
一条消息里两条**文字完全相同**的引用：光靠文字分不出谁是谁 ✗
规则（ccvPinFind）：第 N 条引用 ↔ 第 N 笔上报，从后往前数 ——
  即 remaining = 从这条引用起（含自己）还有几条同篇同文的引用
  取 matched[matched.length - remaining]
⚠️ 这一条曾经写反过（取"最新的那笔"），两条一模一样的引用会**静默对调** ✗
   回归测试：[73a/b/c]（test-host-selctx.cjs）
```

## 8. 症状：**撤销/重做没反应，或有延迟**

```
① 没反应 → 端点存在但界面没接（历史栈在 host 里，面板走 HTTP，两边不连通）
② 有延迟 → 两段叠加：applyWrite → debouncedFlush（**1500ms**）+ 查看器等文件变化才重读
   修法：撤销/重做是**人的一次性动作**，没有连打的场景 → 端点里 await flushDirty() ✓
        客户端拿响应里的 content **当场渲染**（override），props 追上来后丢掉 ✓
```

## 9. 症状：**测试测的是旧代码**

```
host 测试是**从 dist/host.js 里切真代码**跑的（不是照抄一份）✓
所以：改完 src/host/*.js 必须 `npm run build` 再跑测试 ✗
      忘了 build 就会"改了代码测试还是绿的"（或反过来）✗

切块的两个坑：
  · 从**标记本身**开始切（标记写在一行注释里 —— 从标记之后切会把注释尾巴当代码 ✗）
  · 标记没了要**立刻报错**，不能悄悄测过期副本（每份测试都检查这个 ✓）
```

## 11. 症状：**保存时闪一下 / 焦点丢了 / 打字被吞**（2026-10-17 一整轮）

```
这一轮连着出了五个事故 ✗ 全是"编辑区"这块的 ✓ 教训都写在这儿 ✓

① 闪一下（"像刷新了一下"）
   链条：保存 → 文件变 → **宿主（DSH 文档预览）卸载重装我们的组件** ✗
        → 编辑区那个 DOM 元素被销毁重建 ✓ → 闪 ✓
   证据：日志里 `重设正文（实例#2 …）` 的**实例号一直在变** ✓
        而两次之间**没有模块重新加载的日志** ✗ → 是宿主重建 ✓
   ⚠️ 试过"把元素搬到 React 之外" ✗ **失败了三次** ✓
      （每次修好一个又弄坏一个：失焦 → 卡死 → 乱撤销 ✓）
   → 现在只做**降频**：写盘停手 5 秒 **且** 这 1.2 秒内没在打字 ✓
     （见第 12 节 ✓ 别再动 DOM 归属 ✗）

② 焦点丢了（要再点一下才能打字）
   根因：`hadFocus` 是从 `document.activeElement` **反推**的 ✗
        而元素被摘下来/被抢走时它当然不是 activeElement ✓ → 记成 false ✓
   → "原本有焦点才抢"永远不成立 ✓
   正解：**hadFocus 是粘性的** ✓ 只由 `focusin` 按"焦点落在编辑区里/外"决定 ✓
       摘下来 / 被抢走 / 只是失焦 → **一律不动它** ✗

③ 卡死（十几万字的文档）
   根因：`caretOffset` 是**全文 TreeWalker** ✗（O(文本节点数)）
        而它挂在**每次 selectionchange** 上 ✗ 我还写成调两次 ✗✗
   → 每敲一个字全文遍历两遍 ✓ → 14 万字必然卡死 ✓
   规矩：**热路径上任何操作的代价都必须先想清楚** ✓
   现在：rAF 节流 + 只在有焦点时算 + 超大文档（>6 万字）不算偏移 ✓

④ 拼音打一半 → 页面刷新 → **输入全丢**
   根因：`saveDoc` 在 `composing` 时**每 400ms 自我重排一次** ✗
        → 无限循环 ✓ → 而**每行日志都是一次 POST** ✗ → 淹掉浏览器 ✓ → 崩掉刷新 ✓
   规矩：**推迟 ≠ 重排** ✗ 推迟必须有上界 ✓（或者干脆交给"组合结束"那条路 ✓）
   现在：只跳过不重排 ✓ + **log 本身限流**（同句 1 秒一次 ✓）

⑤ 乱撤销 / 空白文档（本地撤销栈那次）
   根因：把"分步撤销"**外挂**在"整篇快照"这套旧机制上 ✗
        （第一个操作的"操作前状态"是空的 → 拿"操作后"当"操作前"✗）
   结论：**A2 不能外挂** ✗ 它必须建立在"模型是唯一真相"之上 ✓
        → 已整个撤掉 ✓ 回到服务端历史（粒度粗 ✓ 但一致、安全 ✓）
```

## 12. 症状：**自动保存太频繁**（写盘时机）

```
成熟软件怎么做的（2026-10-17 查过 ✓）：
  VS Code     默认**关闭**自动保存 ✓ 开了也只是写文件 ✓ 编辑器毫无感觉 ✗
  Google Docs 每敲一个字发 op ✓ 频率更高 ✓ 但服务端**只回 ack** ✗ 从不回灌整篇 ✓
  Obsidian    停手 ~2 秒写文件 ✓ 编辑器不受影响 ✓
→ **频率不是问题** ✓ "保存之后宿主会重建我们的组件"才是 ✗

我们的分工（照抄成熟软件 ✓）：
  · 草稿（localStorage ✓ 不碰文件 ✓ 不影响界面 ✓）→ **勤快** ✓ 800ms ✓ 防丢靠它 ✓
  · 写盘（会触发宿主重建 ✗）→ **懒** ✓
      停手 5 秒 **且** 最近 1.2 秒内没在打字 ✓
      失焦 / Ctrl+S / 切后台 / 关页 → **立刻** ✓
  · ⚠️ 发之前必须再确认一次"你现在没在打字" ✗
    因为"每次输入重置计时器"挡不住"计时器已到点、请求在路上"那个窗口 ✓
    （主人原话：「卡着第五秒打字」✓）
  · 确认在打字 → **跳过这次** ✗ 不是重排 ✗✗（重排就是第 11 节④那个无限循环 ✓）
```
