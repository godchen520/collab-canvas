`src/host/10-editor-code.js` 里的 **12,999 字符 `EDITOR_PANEL_JS` 字符串** —— 早期「浮层面板式编辑器」的整份浏览器端代码，自带一套 `mdToHtml` / `htmlToMd`、划词栏，还有一段把「话布」按钮硬塞进侧栏设置区的 `findSettingsArea` + `setInterval` 逻辑。

## 四、第二轮：子模块公共工具去重

**提交** `8ca5854`

### 问题背景

`docdrop.js` / `doclink.js` 是**「单文件、由 host 按请求供源码」**的模块 —— 改完刷新页面即生效、不用重启。代价是它们**无法互相 require**，只能复制代码，于是日志、轻提示条、会话查询串这三样功能在**三个文件里各存了一份**。

### 解决方案

client.js 挂出全局命名空间 `window.__ccvKit`：

| 方法 | 作用 |
| --- | --- |
| `log(msg, tag)` | 统一走 `/api/canvas/log`，tag 前置成 `[tag]` |
| `toast(msg, id)` | 轻提示条（底部居中、2.2 秒淡出） |
| `sidQ()` | 会话查询串片段（`sid=xxx`） |

`docdrop.js` / `doclink.js` 各加 9 行：**优先取用 `__ccvKit`，取不到再退回自带副本** —— 加载顺序变了也不会坏，向前兼容。

| `docdrop.js` | 16,198 → 16,760（+562） |

## 十、已修 bug：编辑器行内规则跨界配对

**提交** `9809d04` —— 2026-09-12 测试发现并修复

### 现象

文档**只要在话布面板里打开过一次就会被静默改写**。样本：

| 写入时 | 打开后变成 |
| --- | --- |
| `emit(EV.*)` | `` `emit(EV.`*`)` `` |
| `src/host/*.js` | `` `src/host/`*`.js` `` |

### 根因

`mdToHtml` 的行内规则 `im()` 把**代码跨度替换排在强调规则之前**：

```
.replace(/`([^`]+)`/g, "<code>$1</code>")     // 先把代码变成 HTML
.replace(/\*\*([^*]+)\*\*/g, "<strong>$1</strong>")
.replace(/\*([^*]+)\*/g, "<em>$1</em>")        // 再跑强调 → 跨过 <code> 边界配对
```

失效过程（输入 `**移除全部 \`emit(EV.*)\` 调用**`）：

1. 代码跨度先变成 `<code>emit(EV.*)</code>`
2. 粗体规则要求两个 `**` 之间没有 `*`，但 `<code>` 里正好有一个 → **匹配失败**
3. 斜体规则从开头 `**` 的第二个星号起匹配，吃掉 `移除全部 <code>emit(EV.`，撞上代码里的 `*` 收尾 → **跨边界配对成功**
4. 生成非法嵌套 `<em>…<code>…</em>…</code>`，浏览器自动纠正该 DOM
5. `htmlToMd` 把纠正后的 DOM 序列化回 markdown → 反引号位置错乱

### 触发条件

必须同时满足：行内代码里有 `*`，**且该代码跨度被 `**粗体**` 或 `*斜体*` 包着**。单独的 `` `a*b` `` 不受影响。

### 修复

改为「**先抽出、后还原**」：把代码跨度替换成不含标记字符的占位符，跑完全部行内规则再还原。

顺带修掉两个同类问题：

| 输入 | 修复前 | 修复后 |
| --- | --- | --- |
| `` `a~~b~~c` `` | `<code>a<del>b</del>c</code>`（代码里被加删除线） | `<code>a~~b~~c</code>` |
| `` `a==b==c` `` | `<code>a<mark>b</mark>c</code>`（代码里被加高亮） | `<code>a==b==c</code>` |

**回归用例 6/6 通过**（含常规混排）。

### 同源问题：编辑器保存会覆盖 AI 的并发写入

排查本 bug 时发现：话布面板打开时把内容加载进 DOM；此时 AI 用 `canvas_write` 写入

（更新内存 + 文件）；随后编辑器自动保存，把**它那份过期 DOM** 写回去 → AI 的写入丢失。

> 实证：本文档曾被追加过两节内容，之后整段消失（文件从 8,962 字节退回 8,691 字节）。

与上面的 bug 是同一类问题的两面：**编辑器的「markdown → DOM → markdown」往返不保真**。

尚未处理，需要「保存前重读并比对版本」之类的并发保护。

## 十一、已修：编辑器覆盖 AI 写入（并发保护）

**提交** `07df3ba`（客户端）+ `ea2a784`（host）

> 本节闭环第十节末尾记的「同源问题」。那里写的「尚未处理」已被本节取代。

### 是两个 bug 叠在一起

**Bug 1：客户端从不回传版本号**

host 的 `applyWrite` 早就支持乐观并发控制：

```
if (typeof baseVersion === 'number' && baseVersion !== c.version) {
  return { conflict: true, currentVersion: c.version, currentContent: c.content }
}
```

HTTP 端点也已转发 `body.knownVer`。但客户端 `writeMd` 只发 `{ id, content }`

→ `baseVersion` 是 `undefined` → **`typeof` 检查为假 → 直接跳过校验** → last-write-wins。

而客户端其实一直持有版本号（`const [version, setVersion] = useState(0)`），只是没发回去。

**Bug 2：host 端点把冲突伪装成成功**（实测才发现的）

```
const result = applyWrite(...)                    // → { conflict: true, currentVersion, currentContent }
json(res, { ok: true, version: result.version })  // result.version 是 undefined
```

`JSON.stringify` 会丢掉 `undefined` 键 → 响应变成 `{"ok":true}`。

**即使客户端写了处理逻辑也永远收不到冲突。**

对照另外两条通路，它们本来是对的：

`06-rpc.js` → 返回 `E_CONFLICT` + 服务端内容；`07-tools.js` → 返回 `E_CONFLICT` + 提示先 `canvas_read`。

只有 HTTP 这条漏了。

### 修复

**客户端**：

- `writeMd` 回传 `knownVer: versionRef.current`
- 新增 `versionRef`（`version` 是 useState，自动保存跑在 `setTimeout` 里会闭包抓到过期值）
- 新增 `lastSyncedMd`（记录「最后一次与服务端一致的内容」）
- 新增 `resolveConflict()`，两种情形分开处理：

| 情形 | 判据 | 动作 |
| --- | --- | --- |
| ① 本机无改动 | DOM === `lastSyncedMd` | **采用服务端版本** + 提示 ← 这正是本次要修的丢失点 |
| ② 本机有未保存编辑 | 不等 | 不覆盖，仅提示，用户点「重载」 |

**host**：HTTP 端点显式回传

`{ ok: false, conflict: true, currentVersion, currentContent }`

### case ② 为什么不会丢用户的编辑

`scheduleDraft()` 在每次输入时把内容写进 localStorage（`ccv-draft-cache`），

而 `loadCanvas` 检测到「草稿 ≠ 服务端内容」时会**恢复草稿并补写服务端**。

所以情形 ② 保留本地 + 提示之后，用户点「重载」即可看到最新内容，

并且他刚敲的那份会被自动写回去。

### 顺带修的两个往返漂移

同一轮里用 `tools/roundtrip-lab.cjs` 实测发现并修掉：

| 问题 | 根因 | 修复 |
| --- | --- | --- |
| 多级列表缩进累加（三级 4 空格→6 空格） | `serializeLi` 给每行补 `pad`，而嵌套列表已由 `renderListMd(kid, childPad)` 缩进过 → 双倍 | 已带前导空白的行原样输出，空行保持空 |
| 任务列表多一个空格（`- [ ]  内容`） | `mdToHtml` 产出 `input 标签 + 空格 + 内容`，跳过 input 后空格残留在文本节点 | 任务项先剥掉内容前导空白 |

**往返保真从 22/25 提升到 24/25**，仅剩「列表套代码块」（`mdToHtml` 解析器遇空行即结束列表段，按计划搁置）。

## 十二、可点入口：从「手写约定」到「工具驱动」

### 背景：三套可点机制，归属不同

| # | 机制 | 归属 | 触发条件 | 点击打开 |
| --- | --- | --- | --- | --- |
| 1 | **deliverables** | DSH 自带 | 本轮被 `write`/`edit` 改过的文件，正文 inline-code 匹配 | DSH 文件打开器 |
| 2 | **doclink** | 本插件 | 正文出现话布标题（≥4 字符）即自动转链 | 话布面板 |
| 3 | **@ 引用** | DSH 自带 | 输入框用 `@` 选中的文件 | 按类型 |

**关键**：机制 1 不覆盖话布文档 —— `canvas_write` 不在 `write`/`edit`/`str_replace_editor` 之列，

而 deliverables 的词表只从这三者的**参数**里取（`mutationPath(name, argsRaw)`）。

### deliverables 行其实是两行

`Deliverables` 组件同时渲染两个独立子行（`dsh-client-ui-deliverables`）：

```
matched.produced.length > 0  → ProducedFiles（即「本轮文件改动」）
matched.presented.length > 0 → Presented（present 工具声明的文件）
```

**二者并存，互不遮挡。** 而 present 用的通道对任何插件开放：

```
session.append("deliverables/presented", { turn, callId, files })
```

`dsh-session` 的 `append()` 只校验数据形状，**不校验类型白名单**。

### 采用的方案：present 卡片 + 捕获阶段接管

1. 改完话布文档后调用 `present` 声明 `canvas-docs/<标题>.md`
2. 回复末尾出现一张可点卡片
3. doclink 在**捕获阶段**拦下卡片点击 —— 命中话布就开话布面板

为什么要捕获阶段：React 18 把 onClick 挂在根容器上，**冒泡时先于 document 上的监听触发**。

只有捕获阶段才抢得到它前面。实测日志：

```
20:23:19  [doclink] 清单已加载 7 篇
20:23:40  [doclink] presented 卡片点击: 「话布优化.md」命中话布，转开话布面板
```

### 教训：删掉「在回复末尾手写一行入口」的约定

最初的做法是让模型在回复末尾手写一行 `📄 打开话布：<标题>`。

**它连续误触发两次**：只读、只查询、只跑命令的回合也照样附上。

第二次尤其说明问题 —— 第一次之后已把措辞收紧为

「只读、只查询、只跑命令的回合**不要**加这一行」，且确认已生效，**仍然复发**。

> 根因不是措辞，是**约定这个形态本身**：凡是「满足条件 Y 时在回复末尾输出 X」的规则，
> 
> 都容易被当成仪式执行 —— 记住「末尾要加一行」，条件被跳过。

**修法**：不再规定任何手写入口。入口完全由工具驱动 ——

调了 `present` 才有卡片，不调就没有，**没有可被误触发的余地**。

且因 doclink 会自动把正文里的标题转成链接，删掉这条约定**不损失任何能力**。

### 未采用的方案：插件自动 append

理论上可让 `canvas_write` 自己在 `tools/result` 时 `session.append('deliverables/presented')`，

彻底摆脱模型自觉。但没有采用，因为 `turn` 号只能从 `sessionProjections` 取，

而全仓库只有 `dsh-tool-cordis` 提供该服务 —— 依赖它风险偏高，

还会让插件在缺失该服务时挂载失败。

替代做法：把提醒放进**工具返回值**里。工具结果紧跟调用回到模型上下文，

出现在「刚写完文档」这一刻，比提示词里的一条通用约定有效得多。

## 十三、后续修正（2026-09-12 晚）

> 本节修正第十二节的过期结论，并补记同一晚查出的三个缺陷。

### 修正：doclink 的「正文标题自动转链」已整体删除

第十二节末尾写着「doclink 会自动把正文里的标题转成链接，删掉手写约定不损失任何能力」——

**这句在 v4 之后不成立**。该机制已删除，原因有两层：

**1）它会污染正在编辑的文档**

扫描根的选择是：

```
document.querySelector('[data-pane="conversation"]') || document.body
```

选择器一旦没命中就兜底整个 `document.body`，而右侧栏的话布编辑器也在 body 里。

于是文档正文里的 H1「话布优化」被改写成 `<span class="ccv-doc-link">` 并加上

tooltip「点击在话布中打开」—— 用户正在编辑的内容被改写。

**2）已被官方通道取代**

改完话布文档调用 `present` 后，deliverables 行会生成可点卡片，由 doclink 在捕获阶段接管。

入口由工具驱动，不依赖正文里写没写标题。

**删除范围**：`collectTextNodes` / `processTextNode` / `scanRoot` / `scheduleScan`、

`MutationObserver`、`.ccv-doc-link` 两条 CSS 与 `onClick` 里的对应分支，

以及仅供扫描使用的 `MIN_LONG_TITLE` / `MIN_ID_LEN` / `SCAN_DEBOUNCE_MS` /

`escapeRe` / `isWordChar` / `isWrapperChar`。`lib/doclink.js` 26,146 → 21,806 字节。

**保留**：各类文件卡片的点击接管（路径卡片 / 工作区相对路径 / @短名 / 上传卡片 /

deliverables 声明卡片）。它们只在**点击那一刻**判定，且都带 `#collab-canvas-panel` 守卫，

不扫 DOM、不改内容。

**所以现在入口只剩一条路**：

```
canvas_write  →  工具返回值提醒  →  present  →  官方卡片  →  doclink 捕获接管  →  话布面板
```

### 新缺陷一：过期草稿覆盖服务端（数据丢失）

**现象**：本文档两次被整段抹掉（15,101 → 8,691 字节，第十、十一节消失）。

**根因**在 `loadCanvas` 的草稿恢复路径：

```
var dft = draftGet(d.id)
if (dft && dft.content !== d.content) {
  versionRef.current = d.version                                  // 服务端「当前版本」
  setTimeout(function () { writeMd(d.id, dft.content) }, 1500)    // 但内容是旧的
}
```

草稿装的是旧内容，却拿着服务端的当前版本号去写 —— 版本校验当然通过，

旧内容被当成合法写入，直接覆盖。

> **之前的并发修复只堵住了「编辑器保存」这条路，漏了「草稿补写」这条路。**

**修法**：草稿必须记住自己的基准版本。

- `draftSet(id, content, base)` 多记一个 `base`
- 新增模块级 `ccvLiveVer`，用 `useEffect` 每次渲染后镜像 `versionRef.current`

（`draftSet` 是模块级函数，读不到组件内的 `versionRef`）

- `loadCanvas`：base 与服务端版本不一致（含无 base 的旧格式草稿）时**不自动写回**，

只载入服务端内容 + toast 提示；草稿保留在 localStorage，用户内容不丢

### 新缺陷二：存储根兜底写进了 DSH 的安装目录

`docsDirBase()` 的最后一级兜底是 `'.'`（进程 cwd），而 DSH 的 cwd 可能就在自己的包目录里。

实测落到 `node_modules/@deepseek-ai/dsh/lib`，插件把 `file-registry.json` 和

`canvas-docs/.canvases.json` 写进了 DSH 包目录（前者还把 `dsh/lib` 登记成了一个文件夹）。

**修法**：兜底改为用户级稳定目录 `%USERPROFILE%/.dsh-collab-canvas`，

并在走到兜底时打明确的 error 日志。误写的文件已删除。

### 教训：`git add -A` 会替你提交别人的回退

那次丢失之所以进了 git，是因为我只顾着自己改的提示词文件，

`git add -A` 顺手把被面板回退的文档一起提交了。

> **在「数据会被外部进程改写」的仓库里，提交前必须扫一眼 `git status` 的完整改动清单。**

## 十四、已修：同一文件挂多条画布记录（重复画布）

**提交** `c115eee` —— 由另一会话实测发现并报告

> 这是同一晚查出的**第三条**数据丢失路径。三条的共性见本节末。

### 现象

- 重启后出现**两条同名画布**（实例：`cv-mtpq58dy-1` 与 `cv-mtpsd3hw-1`，标题都是「dsh会话列表」）
- 两条的 `filePath` 指向**同一个 md 文件**
- 旧记录的内存内容是过期的；它一旦保存（面板自动保存 / 用户编辑），
  就把文件**覆盖回旧内容** —— 用户以为改好了，实际被静默回滚

### 根因

`src/host/05-mutations.js` 的 `loadFileDoc(filePath, title)` **永远新建 id**：

```js
const id = 'cv-' + Date.now().toString(36) + '-' + (++idSeq)
canvases.set(id, c)
```

而 AI 工具 `canvas_load` 直接调它，**没有任何去重**：

```js
const c = await loadFileDoc(p, args && args.title)
```

同一个文件被加载两次 → 两条记录、同一个 `filePath`。

> 注意：`restore()` 本身按 id 存，**不会自造重复**。重复是**创建路径**产生的，
> 重启只是让它显形 —— 这一点排查时容易搞反。

### 修复（三处）

| # | 位置 | 改动 |
| --- | --- | --- |
| 1 | `loadFileDoc` | 先按归一化 filePath 查已有画布，命中即复用（`activeId` 指向它并返回）。所有调用方自动受益 |
| 2 | `restore()` | 启动恢复时按 filePath 兜底去重，先到先得，跳过重复并打 error 日志（防历史 meta 里已有的重复）|
| 3 | `/api/canvas/load-doc` | 原先只按**标题**去重，标题不同但文件相同时仍会新建一条；补上按 filePath 的匹配 |

### 三条数据丢失路径的共性

| # | 路径 | 过期内容 | 为何通过了校验 |
| --- | --- | --- | --- |
| 1 | 编辑器保存（第十一节） | 面板 DOM 里是旧内容 | 客户端不回传 `knownVer`，服务端直接跳过校验 |
| 2 | 草稿补写（第十三节） | localStorage 里的旧草稿 | 用**服务端当前版本号**当基准，校验当然通过 |
| 3 | 重复记录保存（本节） | 旧记录的内存内容 | 两条记录各自持有 `filePath`，谁也不知道对方存在 |

**共性：写入方持有过期内容，却通过了版本校验。**

所以修复方向也一致 —— 让「写入方基于哪一版」这件事**显式化**：
路径 1 补 `knownVer`、路径 2 给草稿记基准版本、路径 3 以归一化文件路径作唯一键。

### 教训

> 「按标题去重」不足以保证文件唯一性。凡是以文件为后端的记录，
> 都应该把**归一化后的文件路径**当作唯一键。
