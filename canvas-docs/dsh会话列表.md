## ⚠️ 会话管理须知（踩过的坑）

**绝对不要在 `E:\DeepSeek Harness\.dsh\sessions\` 内部创建任何非标准文件夹。**

DSH 启动时会扫描该目录下**所有**子文件夹（连不认识的名字也照扫），一旦发现里面有会话文件、且其"记录的归属工作区"与"实际所在路径"不匹配，就会判定 `corrupt session log` 并**拒绝启动**。

> 2026-09-12 曾把 15 个会话移入 `sessions\_deleted_backup\`，导致 DSH 启动即崩溃。报错里的 "corrupt" 是误导——**文件内容完好，只是位置不对**。

### 正确做法

| 操作 | 正确方式 |
| --- | --- |
| 隔离/删除会话 | 移到 **`sessions` 目录外面**，或直接送回收站 |
| 判断某会话是否归档 | 查 `workspace.json` 的 `global.archivedSessionIds` |
| 修改注册表 | 先备份 `workspace.json`；DSH 不会重扫磁盘重建它 |
| 删除会话的完整步骤 | 确认注册表无引用 → 删目录 → 校验"磁盘数 == 注册表数" |

### 存储格式

- **v3（当前）**：`session.v3.jsonl.zstd` —— DSH 0.1.5+
- **v1（旧）**：~~`session.jsonl.zstd`~~
- 同一会话可能两种格式并存，**体积不可直接比较**（v1→v3 是压缩差异，非内容丢失）
- 扫描时务必匹配 `session.v3.jsonl*`，只匹配 `session.jsonl*` 会漏掉新格式会话
- 📌 实测：8 个会话中 7 个仍同时存在 v1 文件（只有新建的空会话是纯 v3），所以 v1 是**旧格式**而非"已不存在"
