### 五项设计原则

| # | 原则 | 豆包的实现 |

|---|------|----------|

| 1 | **AI 置顶** | 每个菜单的第一个选项都是 AI 入口（「问豆包」「AI帮我写」） |

| 2 | **图标即操作** | 常用格式用图标（H1-H4/B/I/U），操作级功能用文

| 3 | **渐进披露** | 简单选项直接可见，复杂选项用 › 箭头暗示子菜单 |

| 4 | **分组有逻辑** | 基础→常用→小组件，按使用频率从高到低 |

| 5 | **上下文感知** | 选中标题后 H3 高亮当前级别，用户一眼知道状态 |

## 二、操作菜单深度分析（选中文字 → ⋯）

### 2.1 层级结构

```
┌─────────────────────────────────────┐
│  🗨️ 66  问问豆包                   │  ← AI 问答（置顶，最高优先级）
├─────────────────────────────────────┤
│  T  [H1] [H2] [H3] [H4]  📋       │  ← 行1：格式图标（H3高亮=当前状态）
│  ☑  {}  「」  ↔                    │  ← 行2：任务/代码/引用/缩进
├─────────────────────────────────────┤
│  缩进和对齐  ›                      │  ← 子菜单提示
│  颜色  ›                            │  ← 子菜单提示
│  ──────────────────                 │
│  评论                               │  ← 操作区
│  剪切  复制  翻译                    │
│  删除                               │
├─────────────────────────────────────┤
│  分享  复制链接                      │  ← 信息操作
│  在下方添加  ›                      │  ← 切换到创建路径
└─────────────────────────────────────┘
```

### 2.2 关键设计细节

**1) 格式行的图标矩阵**

H1-H4 四个标题级别横向排开，选中的那个有蓝色高亮（截图中 H3 高亮）。这种设计让用户：

**不用打开子菜单**就知道当前是什么格式

**一键切换**标题级别（点 H2 就切换到二级标题）

**视觉反馈即时**——不需要回到主菜单确认

**2) 操作项的视觉分组**

豆包用 **细线分割符** 将操作分为三组：

格式区（图标行）

操作区（剪切/复制/删除——需要上下文的动作）

分享区（传播相关）

每组之间有明确的视觉边界，用户心理预期清晰。

**3) 「在下方添加」的双重身份**

「在下方添加」在操作菜单底部出现，但它实际是**切换到创建路径的入口**——点击后弹出内容插入菜单。这是一个优雅的「路径桥接」。

## 三、插入菜单深度分析（行首「+」）

### 3.1 层级结构

```
┌─────────────────────────────────┐
│  🤖 AI 帮我写                  │  ← AI 生成入口（置顶）
├─────────────────────────────────┤
│  【基础】                       │
│  H1 H2 H3 H4  有序 无序       │  ← 图标网格（紧凑排布）
│  ☑  {}  「」  🔗               │  ← 任务/代码/引用/链接
├─────────────────────────────────┤
│  【常用】                       │
│  ☑ 任务                        │
│  🖼️ 图片  📎 视频或文件        │  ← 媒体类
│  📊 表格  ›  ❓ 分栏  ›        │  ← 复合组件（可配置参数）
│  🟡 高亮块  πₓ 公式           │  ← 装饰/学术组件
├─────────────────────────────────┤
│  【文档小组件】                  │
│  🎨 文本绘图                    │  ← 高级/AI组件
└─────────────────────────────────┘
```

### 3.2 关键设计细节

**1) AI 始终第一位**

无论操作菜单还是插入菜单，AI 入口都是第一个选项。这不是「锦上添花」，而是「设计意图」——豆包想让用户**养成「先问 AI」的习惯**。

**2) 图标 vs 文字的切换策略**

| 区域 | 展示形式 | 原因 |

|------|---------|------|

| 标题级别 | 纯图标（H1-H4） | 高频操作，图标足够表达 |

| 列表 | 图标（有序/无序） | 同上 |

| 任务/代码/引用 | 图标 | 空间紧凑 |

| 图片/视频/表格 | 文字+图标 | 需要说明具体类型 |

| 高亮块/公式/文本绘图 | 文字 | 较少用，文字更清晰 |

**3) 「基础→常用→小组件」的渐进复杂度**

用户从上往下看，遇到的复杂度逐步提升：

基础：标题、列表——所有人都会用

常用：图片、表格——大多数文档场景需要

小组件：文本绘图——只有特定需求才用

## 四、对共创话布的借鉴清单

### 4.1 可直接借鉴（低复杂度）

| 借鉴项 | 豆包做法 | 话布当前 | 改造方案 |

|--------|---------|---------|---------|

| **H1-H3-H4 快捷** | 图标横向排开 | 只有 H2 | 在划词栏增加 H1/H3/H4 |

| **当前格式高亮** | 选中标题后 H3 蓝色高亮 | 无 | 用 execCommand 查询当前格式 |

| **AI 入口置顶** | 「问豆包」在菜单第一位 | 无 | 划词栏加「问 AI」按钮 |

| **视觉分隔符** | 菜单项间有细线 | 有（ccv-menu-sep） | ✅ 已实现 |

| **渐进披露箭头** | 复杂操作带 › | 无 | 完整菜单的子菜单 |

| **「在下方添加」** | 操作菜单末尾的路径桥接 | 无 | 行首「+」按钮 |

| **图片插入** | 插入菜单「图片」项，支持粘贴/拖拽/文件选择 | 不支持 | contentEditable 原生粘贴图片 → base64 存入 Markdown → 编辑器内 `<img>` 渲染 |

### 4.2 需要设计评估（中复杂度）

| 借鉴项 | 豆包做法 | 评估 |

|--------|---------|------|

| **行首「+」插入菜单** | 点击段落左侧弹出块类型菜单 | 核心差异：话布是内容编辑器，不是文档。是否需要块级插入取决于功能定位 |

| **「缩进和对齐」子菜单** | 点击展开更多选项 | 可在完整菜单中用分组代替 |

| **「颜色」子菜单** | 文字颜色/高亮背景 | Markdown 不直接支持颜色，需决策是否引入扩展语法 |

| **评论功能** | 段落级评论 | 需要 AI 协作场景才有价值 |

## 四、实现优先级建议

### P0 — 立即可做

**划词栏增加 H1/H3/H4**：在 `CANVAS_SELBAR_SPEC` 里加 `{label:'1',cmd:'formatBlock',val:'<h1>'}` 等

**当前格式高亮**：execCommand 查询 `queryCommandState('bold')` 等，高亮当前格式按钮

**AI 问答入口**：划词栏加「?」按钮，预填选中文本发起 AI 问答

### P1 — 下次迭代

**完整菜单增强**：增加表格/分栏/代码块等块级元素

**行首「+」按钮**：鼠标悬停段落左侧出现，点击弹出插入菜单

**图片支持**：粘贴/拖拽/文件选择器插入图片，存储为 base64 内嵌于 Markdown（`![alt](data:image/png;base64,...)`），编辑器内实时渲染

**评论功能**：段落级 AI 评论/批注
